# SFT pilot dataset

[Introduction](Introduction.md)

Goal: 20 verified examples (10 math, 10 CS). Each example: a natural-language problem, its Lean formalization, a natural-language solution with the CoT leading to it, and a verified Lean proof with the CoT leading to it. Generated by a self-organizing swarm of copies of one open model (e.g. Qwen3.8-27B, quantized). Each run yields one SFT trace per agent.

## Environment

Bash + a shared folder + one communication channel, per [Agent environment](Agent-environment.md). No roles, no turn-taking, no imposed workflow. The prompt names the medium, not the protocol.

Communication channel: a single append-only log `chat.log` in the shared folder.

- One message = one short JSON line: timestamp, `$AGENT_ID`, text. Appends are atomic on a local POSIX filesystem; no lost or interleaved messages.
- Broadcast only. No inboxes, routing, or acknowledgments; point-to-point is an emergent convention (`@B2: ...`). A dead agent blocks no one.
- Total order is recovered by parsing timestamps after the run.
- The environment injects `$AGENT_ID`; the prompt only states: *"chat.log is a shared channel; every agent can read and append; use it as you see fit."*
- The shared folder is the second, implicit channel: artifacts communicate. Concurrent overwrites remain possible and observable.

## Acceptance gates (external)

The harness checks the final folder state, never the path taken. For each problem the folder must contain `P.md`, `F.lean`, `S.md`, `V.lean`, with:

- `F.lean` compiles, no `sorry`, no extra axioms; statement not closed by `decide`/`simp` (else tagged trivial and replaced).
- `V.lean` proves `F.lean`.
- Independent recompilation in a frozen Lean project, outside the generated harness (see [Related work](Related-work.md) on verifier exploits).

## Runs

- Problems: 10 math (induction, modular arithmetic, elementary inequalities, counting), 10 CS (algorithm correctness: sorting, `reverse ∘ reverse = id`, graph reachability, loop invariants; formalization includes defining the algorithm). CS statements use simple definitions over mathlib/`Std`.
- Same system prompt for every agent: mission (produce the four artifacts), environment description, acceptance criteria. Nothing else.
- Each problem runs across swarm sizes 1, 2, 4 and multiple seeds. Record all traces, including silos, redundancies, and failures (`failures/`). Diversity of organizations is a feature.
- Budget: token cap and compiler-round cap per run; failed runs are recorded, not retried by the harness.

## Trace selection (filtered behavior cloning)

Score each trace from objective logs:

| Criterion | Measure |
| --- | --- |
| Success | Complete verified quadruplet under budget. |
| Efficiency | Total tokens, compiler rounds, elapsed time. |
| Collaboration | Agents contributing to final artifacts; reuse vs overwrite of others' work; message-graph connectivity; any NL↔Lean cross-check. |
| Redundancy | Duplicated or discarded work. |

Select for diversity, not only score: solo-efficient traces on easy problems and highly organized traces on hard ones are both kept — the organization/difficulty trade-off should be learned, not assumed. Human review of the final 20 quadruplets. Rejected traces are kept for later preference pairs and for [controls](Experimental-controls.md).

## Loss masking

Per agent, one training sequence per run:

| Token source | Loss |
| --- | --- |
| System prompt, problem statement | masked |
| Other agents' messages | masked |
| Own reasoning (CoT, abandoned branches) | trained |
| Own tool-call arguments (e.g. the Lean file submitted) | trained |
| Tool outputs (compiler errors, results) | masked |

Messy CoT is kept: iteration against the compiler is the behavior being taught. Token imbalance across agents is handled at sampling time.
